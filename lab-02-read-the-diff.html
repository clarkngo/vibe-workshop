Read the Diff

Five realistic diffs. Each one has something wrong. Apply Module 02's three-question skim — what changed, does it match intent, any red flags — to each before revealing the answer.

Duration: 20 min Group size: individual or pairs Needs: nothing — read on screen or print
1

Diff A — "add input validation to the signup form"

  function validateEmail(input) {
+   if (input === null) {
+     return false;
+   }
    return true;
  }
Reveal what's wrong

It checks for null but not an empty string, whitespace, or a malformed address — it will accept "" as valid. The change matches the words of the request ("add validation") without matching the intent (reject bad emails).

2

Diff B — "fix the date formatting bug on the invoice page"

  import { formatDate } from './utils/date';
+ import { sendAnalyticsEvent } from './utils/analytics';

  function renderInvoiceDate(invoice) {
+   sendAnalyticsEvent('invoice_viewed', { id: invoice.id });
    return formatDate(invoice.date);
  }
Reveal what's wrong

An analytics call was added that has nothing to do with date formatting — scope creep, and a new side effect (a network call, on every render) that nobody asked for and nobody's reviewing for correctness.

3

Diff C — "handle the case where the API call fails"

  async function loadProfile(userId) {
+   try {
      const res = await fetch(`/api/users/${userId}`);
      return await res.json();
+   } catch (err) {
+     console.log('profile load failed');
+     return {};
+   }
  }
Reveal what's wrong

It "handles" the failure by silently returning an empty object — every caller downstream now gets a profile with no fields and no signal anything went wrong. This is the hallmark of an error being swallowed instead of handled.

4

Diff D — "connect this to the weather API"

  function getForecast(city) {
+   const apiKey = "wk_live_9f2a7c1e4b8d3a20";
    return fetch(`https://api.example.com/forecast?city=${city}&key=${apiKey}`);
  }
Reveal what's wrong

A live API key hardcoded directly into source. Anyone with repo access — or anyone who finds it in a public commit — has it now. This is exactly the class of thing the Responsible Use Policy warns about, just going the other direction: out of the code instead of into a prompt.

5

Diff E — "rename the `total` variable to `orderTotal` for clarity"

- function calculateTotal(items) { ... }
+ function calculateOrderTotal(items) { ... }

- const total = calculateTotal(cart);
+ const orderTotal = calculateOrderTotal(cart);

- exports.calculateTotal = calculateTotal;
+ exports.calculateOrderTotal = calculateOrderTotal;
Reveal what's wrong

Maybe nothing — but check: is calculateTotal exported and used elsewhere in the codebase? A rename that crosses a module boundary can silently break every other file that imports the old name. "Looks right" here depends on information this diff alone doesn't show you.

Debrief

  • Diff E is a trick — it might be totally fine. What would you actually need to check before approving it?
